# 三端同步实测（2026-09-26）

本次使用真实的本地 Worker、macOS App、iPhone 模拟器 App 和浏览器完成同步测试。三端笔记最终一致；配对、双向编辑、离线补同步、删除传播和重启恢复均通过。

## 环境和方法

- 服务：当前工作区代码构建的 Worker，`http://127.0.0.1:8791`，独立的本地持久化目录。
- 浏览器：Codex 内置浏览器，实际打开 `/note` 并操作配对、新建、编辑、保存、删除和刷新。
- macOS：当前工作区的原生 `NoteBatonMac`，使用 Computer Use 操作实际界面。
- iPhone：iPhone 18 Pro 模拟器，iOS 27，实际安装并运行 iOS App。
- 拓扑：浏览器与 Mac 配对，Mac 生成设备邀请，iPhone 接受邀请；笔记通过 Mac 在三端传播。

测试从当前源码复制到临时目录构建，使用独立 Bundle ID、钥匙串命名空间和 Mac 数据目录，并关闭自动剪贴板导入。测试仅创建 `E2E` 笔记，没有使用用户原有笔记。

Device Hub 的 Computer Use 接口持续超时，因此 **iPhone 的点按、粘贴和确认界面操作尚未完成验收**。iPhone 端采用仅存在于临时源码副本的集成驱动，调用正式 `ClipboardStore.connect/save/delete`；网络、加密、钥匙串、本地数据库和同步实现均使用真实代码，没有模拟服务或伪造同步结果。驱动只允许连接上述本地测试地址。

最后移除驱动启动参数，正常重启 iPhone App，再次核对实际界面截图和两端数据库。该次重启仍正常连接，保留全部三条测试笔记，已删除笔记没有复现。临时驱动和隔离配置均未加入产品源码。

## 发现与修正

网页的步骤文案仍引用旧名称“配对与服务”。已同步更新为“配对与同步 / Pairing & Sync”，与新版 App 入口一致。

本次未发现三端同步链路故障。尚未覆盖 iPhone 手动配对界面、真机摄像头扫码、生产部署和跨公网网络条件。

## 菜单栏常驻回归

新增菜单栏常驻后，使用独立 Bundle ID、钥匙串和本地笔记目录的 Mac 测试副本重新与本地网页配对，验证：

- macOS 与 iOS Simulator 构建、翻译一致性检查、签名校验通过。
- 系统菜单栏出现 NoteBaton 图标。
- `⌘W` 关闭主窗口后，系统窗口清单确认测试 App 没有可见窗口，进程仍运行。
- 在此状态下从网页更新笔记，网页收到保存确认，Mac SQLite 中包含最新完整正文；再次检查窗口清单仍无可见窗口。
- `⌘Q` 明确退出后进程结束，网页显示等待设备并禁用写入。重新启动后保留配对并恢复同步。
- Computer Use 无法定位系统状态栏图标，菜单内“打开 NoteBaton”和“退出 NoteBaton”的实际点按尚未自动验收。窗口恢复与退出生命周期已验证，不将其等同于菜单项点按测试。
