# iOS、macOS 与 Web 同步

3.2 新增原生设备副本协议 v1；底层沿用 Relay API v3、配对链接 v2 和端到端加密 v1。Worker 不保存正文或同步密文。现有 iOS 本机 SQLite 原地迁移，笔记、删除标记、已有网页授权与每服务身份保留。原生设备间配对需两端升级到 3.2，同时升级 Web / Worker；已有 Web 配对仍兼容。

## 连接方式

每台原生设备有独立 owner 身份及 SQLite 库，既能服务网页，也能作为 peer 连接另一台原生设备。一次只连接一个服务，同一服务下可建立多条设备连接。每次授权会双向合并两端所有本机笔记，因此请只配对自己的设备。

新设备生成邀请，旧设备扫描或粘贴链接并确认。邀请通过 `POST /api/pair {e2eeVersion:1,clientType:"native"}` 创建；密钥仍由邀请端本地生成，位于链接 fragment。服务器记录 `kind=native`，原生授权 365 天，网页保持 7 天。批准 API 返回 `kind`；主设备在本地密钥记录中保存此权限。原生 claim 返回 bearer token、deviceId、peerId、expiresAt，不设置浏览器 Cookie。改变 claim 参数不能把网页授权升级为原生授权。

原生身份和链接凭证分别保存在 `WhenUnlockedThisDeviceOnly` Keychain。每条连接都使用已有 HKDF/AES-GCM 的独立随机握手与方向密钥；`secure-ready` 声明 `replicaVersion:1` 和本机数据库的 `replicaID`，老客户端不能误处理设备副本。协议里的 `phone` / `browser` 是历史密码学方向标签，保持原值以兼容 Web，并不限制物理平台。

## 本地记录与冲突

原生数据库增加 `replica_state`、递增变更序号、持久设备 UUID 和每条链接的已确认游标。所有笔记变更、版本向量和删除标记在同一 SQLite 事务提交，落盘后才发送确认。数据库迁移会为已有笔记和删除标记生成初始向量。

记录为 `{id,text:string|null,createdAt,updatedAt,version:{replicaUUID:counter}}`。`text:null` 是永久删除标记。版本向量区分因果修改和并发修改；每次本机写入递增自己的计数。Web 保留原来的 `baseRevision` 乐观锁，展示版本为向量计数总和。

- 已知或较旧的记录幂等忽略，不产生新序号。
- 后继修改覆盖旧正文；无需依赖各设备时钟决定先后。
- 并发不同正文按正文哈希确定同一获胜内容，另一份保存到由原 ID 和正文哈希生成的稳定 UUID，重试不会无限生成副本。
- 删除标记不允许复活原 ID。并发删除/编辑保留编辑为独立副本；已被因果覆盖的旧正文不恢复。
- 同步冲突副本也能编辑和删除；普通笔记不会因为设备初次同步而按正文去重，原有 ID 保持不变。

## 加密业务消息

仅持有本机 `kind=native` 密钥的连接可使用：

- `replica-list {after:非负整数}`：按本地变更序号读取，每次最多 10 条。每条用独立加密 `replica-item {change:{sequence,record}}` 帧返回，最后发送 `replica-page {cursor,hasMore}`。
- `replica-merge {record}`：本机验证、事务合并，返回 `replica-merged`。正文和游标全部位于密文中。

客户端先拉取并提交，再推送本地差异；只有处理/确认成功才推进游标。断线或确认丢失可重试。游标同时绑定远端数据库 replicaID；重装 App 后 Keychain 身份仍在但数据库已更换时，会从零重传，以便从存活设备恢复副本。更改通知驱动即时同步，10 秒心跳也执行差异检查；每个推送/分页请求间至少 40ms，原生连接上限 2400 帧/分钟（网页仍为 240）。分页按变更序号推进，扫描期间再次修改会获得新序号，不会因为排序移动而漏掉。接收的变更继续通知其他设备及本机授权网页。

## 在线边界与撤销

iPhone App 在前台、Mac App 运行且网络在线时同步。Mac 窗口不活跃仍保留连接，但不持续读取其他应用剪贴板。后台 iPhone 不能持续同步；重回前台重新握手并补齐。网页仅保留本页已读取内容和草稿，仍需其授权设备在线才能保存。

连接形成用户明确授权的设备网络。A–B–C 需要 B 在线才能在 A 与 C 之间传播；可显式增加 A–C 连接。不会共享 owner 身份或隐式把所有设备授权给别人，也不自动替换网页绑定的设备。没有服务器排队、云备份或账号找回。

撤销主设备上的授权会先删除本机密钥再撤销服务端权限；发起设备可以移除自己的链接。已同步副本不会远程擦除。离线期间删除和冲突将在后续同步传播，重要内容仍应另行备份。
