# 网站与政策模板

开源仓库保留官网界面、政策模板和 App 的本地资源，便于阅读与开发。正式 App 的签名、安装包、公证、App Store 审核资料及发布者配置在独立发布仓库维护。

用户自部署笔记服务无需填写运营者、App 开发者或联系邮箱。默认 `npm run build` / `npm run deploy` 不读取这些资料，也不包含官网页面。

## 不含发布者身份的模板

`web/site.config.json` 中的 `webOperatorName`、`webPrivacyEmail`、`appDeveloperName`、`appPrivacyEmail` 在本仓库保持 `null`。公开的 GitHub 地址、产品域名与模板日期可以保留。检查脚本会拒绝将实际发布者资料加入此文件。

英文模板位于 `web/legal/`，简体中文位于 `web/legal/zh-CN/`。运行 `cd web && npm run build:legal`，生成网站页面及 `ios/Clipboard/Legal/` 中的 App 离线正文。缺少发布者资料时会显示草稿提示，网站同时带 `noindex`。这些草稿用于源码开发，不代表线上服务当前的政策。

正式隐私政策请查看 [官网政策](https://notebaton.org/app-privacy/)。本仓库的修改不会更新已发布 App 或线上网站。

## 本地预览

```sh
cd web
npm ci
npm run build:site
npm run dev:api:site
# 另一个终端运行：
npm run dev:site
```

官网源码构建到 `dist/site/`，使用 `wrangler.site.jsonc`；自部署服务构建到 `dist/relay/`，使用 `wrangler.jsonc`。官网模板包含首页、笔记、下载入口、政策及支持页，下载链接指向外部已发布资源。两种构建均不包含 App 安装包。

`npm run build:app-resources` 生成翻译、Markdown、第三方许可和本地政策资源，供源码编译使用；CI 只进行测试和无签名编译，不归档或发布 App。

## 独立网站发布

需要发布自有产品网站的维护者，应在自己的发布副本中填写实际公开资料，并运行 `npm run build:site && npm run check:legal:release`。`npm run deploy:site` 保留相同发布检查，默认的空白模板不会通过。

官网本机部署目标使用被忽略的 `.deploy.site.local.json`，自部署目标使用 `.deploy.local.json`，两者应使用不同 Worker 名称。不要将正式发布资料或构建产物复制回本开源仓库。
