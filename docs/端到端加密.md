# 端到端加密 v1

适用于 App / Web 3.0 和 Relay API v3。实现使用 Web Crypto 与 Apple CryptoKit；不自行实现密码算法。生产环境继续使用 HTTPS/WSS。

## 配对与密钥

网页在本地生成 32 字节密码学随机配对密钥。二维码与复制链接为 `https://服务域名/pair#v=2&code=RLY-…&key=<64位小写hex>`；手动方式为 `RLY-….<64位小写hex>` 并另填服务网址。

密钥只通过用户扫描、粘贴或输入交给手机，**不放进 API 请求、Cookie、WebSocket、日志或服务器数据库**。fragment 不随 HTTP 请求发送，但复制链接本身是秘密，不能公开分享。旧短码没有密钥，不能继续用于加密配对。

网页 claim secret 和手机 identity secret 仍用于服务端鉴权，与端到端密钥独立。服务端返回的 `peerId` 用于绑定两端密钥；只有能证明持有配对密钥的客户端才能交换笔记。

手机按服务 origin、deviceId、peerId 将配对密钥存入 `WhenUnlockedThisDeviceOnly` Keychain；本地授权期限最多 7 天，不依赖后端延长。网页把不可导出的 HKDF `CryptoKey` 存入该 origin 的 IndexedDB，关闭和刷新网页后可继续使用；退出、授权失效或丢失密钥后必须重新配对。正文仍只在页面内存中。

## 每次连接

1. 网页建立 `/api/events?v=3`，获得连接 ID；生成 32 字节 `clientNonce`，发送 `hello`。
2. 手机仅为本地存在且未过期的配对生成 32 字节 `phoneNonce`，派生两把独立方向密钥，返回加密的 `secure-ready`。
3. 网页成功解密后才显示加密连接成功并请求笔记。手机首次收到通过认证的加密请求才会处理它。
4. 重连或手机重新上线时创建新会话，不复用旧计数器。失败时停止该连接，不退回明文协议。

会话上下文 `L` 为以下 UTF-8 字符串以单个 LF 拼接，无结尾 LF：

```
relay-e2ee-v1
origin（无尾部斜杠）
deviceId（小写 UUID）
peerId（小写 UUID）
connectionId（小写 UUID）
clientNonce（64 位小写 hex）
phoneNonce（64 位小写 hex）
```

HKDF-SHA-256：输入为配对密钥，salt 为解码后的 `clientNonce || phoneNonce`，info 为 `L + LF + direction`，输出 32 字节。方向分别为 `browser-to-phone` 和 `phone-to-browser`。

AES-256-GCM：认证标签 128 位；每方向独立序号从 1 开始，上限 `2^32-1`。12 字节 nonce 为 8 字节零加 4 字节大端序号。AAD 为 `L + LF + direction + LF + 十进制序号`。密文采用标准 Base64 编码 `ciphertext || tag`，不包含 nonce。

消息外层为 `{type:"sealed"|"welcome",v:1,clientNonce,phoneNonce,seq,ciphertext}`，手机发送时附加路由 `peerId,connectionId`。收件方只接受严格递增的下一序号，并验证上下文和 GCM 标签。网页按顺序执行异步加解密，手机顺序处理收件消息。

正文、笔记 ID、时间、版本、分页游标、增删改操作及业务错误全部位于密文内。每条解密后的 JSON 最多 800,000 字节；密文帧最多 1,100,000 字节，支持单条 100,000 个 Unicode 码点（包括 JSON 转义产生的膨胀）。分页逐条发送。

## 中转能看到什么

中转只需知道设备和网页身份、连接 ID、随机握手值、序号、消息长度、时间及在线状态；仍可观察通信元数据、阻断或延迟消息。它没有笔记解密密钥，不持久保存密文正文。后端只转发白名单字段，拒绝旧明文同步帧。

在手机撤销配对时，先删除本机对应密钥和会话，再调用服务端撤销 API。即使网络请求失败，该手机也不会继续为此配对提供笔记。已在网页读取或复制的内容无法追回。

## 明确边界

- 网页解密代码仍由网站提供。若网站发布了恶意 JavaScript，或设备、浏览器扩展被控制，攻击者可能在端点读取明文或使用密钥。不可导出密钥不能阻止同源恶意代码使用它。自部署及可信前端仍然必要。
- 此版本使用随机预共享密钥和会话派生，**不提供前向保密**：配对密钥日后泄露可能使已录制的历史密文被解密。不是经独立密码学审计的协议。
- 本机 SQLite 和浏览器显示内容没有额外的应用层静态加密；依赖设备保护。卸载 App 仍会丢失笔记。
- v1 云端旧笔记迁移是独立的历史导入接口，只受 HTTPS 保护，不能追溯变成端到端加密；迁入手机后的新同步使用本协议。

## 3.2 原生设备扩展

iOS 与 macOS 复用以上加密协议与方向标签。新设备在本地生成配对密钥，双方通过确认的链接交换；服务器仅保存 `kind=native` 元数据，凭证和密钥不共用。原生密钥本地期限最多 365 天，网页仍为 7 天。每条设备连接单独握手，副本记录、版本向量及游标也全部加密。每台原生设备保留本地正文和删除标记。详见 [多设备同步](多设备同步.md)。原有 Web 授权及 v3 加密传输保持兼容，新增原生复制需要两端 App 和 Worker 升级。
