# 部署自己的 NoteBaton 笔记服务

自部署只提供笔记显示与编辑、配对、同步和中转 API。打开根网址即进入笔记或配对界面；不包含官网首页、App 下载、隐私政策、用户协议或支持页面，不需要填写运营者、App 开发者或隐私联系邮箱。

网页、API 和 WebSocket 放在同一个 Cloudflare Worker。同一个 iPhone 或 Mac 客户端可连接不同部署，配对时自动识别网址；无需改 App 或重新打包。

## 准备

- Cloudflare 账号；电脑安装 Node.js 22.12+ 和 npm。
- 下载或克隆**完整项目源码**，保留并列的 `web/`、`ios/` 和 `shared/` 目录。
- 已发布客户端从[官网](https://notebaton.org/download)获取，也可以按 [iOS 说明](../ios/README.md) 自行构建。使用发布版连接自部署服务无需重新编译。

## 首次部署

在 `web/wrangler.jsonc` 中把 `name` 改成你选择的名称，例如 `my-relay-notes`。后续更新保留相同名称与 migrations。公开配置不包含维护者的账号或生产网址。

```sh
cd web
npm ci
npx wrangler login
npm run typecheck
npm run deploy
```

`npm run deploy` 只构建自部署资源到 `web/dist/relay/`，使用 `web/wrangler.jsonc`；不会读取 `web/site.config.json` 或执行官网政策发布检查。

成功后终端会显示你的 `https://my-relay-notes.<你的子域>.workers.dev` 地址。无需数据库 ID、共享账号密码、服务端密钥或其他人的 Cloudflare 账号；Durable Objects 随部署创建。Cloudflare 的使用额度与计费按你的账号套餐执行。

如果需要从一份源码部署多个实例，可显式指定名称（后续更新也使用同一参数）：

```sh
npm run deploy -- --name another-relay-notes
```

每个实例有独立的配对空间。不要删除已有迁移记录；改 Worker 名称会创建另一个实例，不会迁移旧授权。全新实例不会携带原项目的笔记或配对。

维护多个实例时，也可复制 `web/.deploy.local.json.example` 为 `web/.deploy.local.json`，设置本机默认实例名称。可选的 `domain` 字段指定自定义域名，例如 `{"name":"my-notes","domain":"notes.example.com"}`；部署时会同时保留 workers.dev 地址。该文件不提交 Git；显式 `--name`、`--config` 或 `--env` 优先于本地默认配置。Cloudflare Git 构建使用仓库中的公开配置，不读取你的本地文件。

## iPhone 或 Mac 连接

1. 打开自己部署的网站，点击“显示配对码与二维码”。
2. App →“配对与同步”：扫描二维码，或粘贴“复制完整配对链接”得到的链接。
3. 确认 App 显示的是你的域名，再点“授权此网页”。保持 App 在前台，网页会收到最近 10 条笔记。

加密配对字符串不包含网址。手动输入完整字符串时，同时填写它所属网站的 HTTPS 根地址。已连接过的服务保存在 App 中，可切换或断开；一次只连接一个服务。笔记仍属于同一份本机库，**切换服务不是切换笔记库**。目标服务上的已授权网页可以读取、编辑这些笔记；切回旧服务后，未过期的配对仍有效。移除网页权限需先连接它所属的服务。

## 自定义域名与自动部署

域名还在切换 nameserver 时可先使用 workers.dev。即使已添加域名绑定，也要等 Zone 变为 Active、DNS 和 HTTPS 证书生效后才能正常使用。

在 Cloudflare Worker 的 Settings → Domains & Routes 添加 Custom Domain，然后直接从该域名打开网页配对。网站根据当前域名生成二维码，App 不依赖固定服务器。域名变化视为新服务，需要重新配对；不会自动把旧凭证发送给新网址。

需要 GitHub 自动部署时，将代码放入自己的仓库，在 Cloudflare Workers Builds 连接该仓库，根目录设为 `web`，构建命令 `npm ci && npm run build`，部署命令 `npx wrangler deploy`。Dashboard Worker 名称必须与 `web/wrangler.jsonc` 的 `name` 一致。不要把 `.private/`、`.dev.vars`、Apple 签名文件或令牌提交到仓库；本项目的 `.gitignore` 已排除这些路径。

官方文档：[静态资源与 Workers](https://developers.cloudflare.com/workers/static-assets/get-started/) · [Git 构建配置](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)

## 数据与信任边界

- 已同步的 iPhone 与 Mac SQLite 各自保存正文；网页只保留当前页面内存，后端不保存正文。
- 后端保存设备凭证的哈希、网页授权、短期配对及限速信息。源代码中的旧版迁移对象仅兼容已有部署，新安装不会写入笔记。
- App 与网页端到端加密，API 无解密密钥；连接同时受 HTTPS/WSS 保护。网站提供的前端代码仍必须可信，详细边界见 [加密说明](端到端加密.md)。
- 网页授权设备离线时不能加载或保存；iPhone 需保持前台，Mac App 需保持运行。原生设备可离线编辑并在重连后补齐，没有云备份。
- App 拒绝服务重定向。请填写最终 HTTPS 根网址，不使用短链接、跳转网址或 `/api` 子路径。

## 验证与排错

根路径 `/` 和兼容入口 `/note` 都打开笔记服务，`/pair` 保留为配对链接入口。网站支持中英文切换。`/download`、`/downloads/`、`/privacy/`、`/terms/`、`/app-privacy/` 和 `/support/` 在自部署中返回 404；这些文件也不会进入部署产物。第三方开源许可作为 `third-party-notices.txt` 随软件保留。

浏览器打开 `https://你的域名/api/info` 应返回 `product: relay-clipboard`、`protocolVersion: 3`、`pairingLinkVersion: 2` 和 `e2eeVersion: 1`。这只是兼容性检查，不能证明服务运营者可信。

- “不兼容服务”：确认部署的是当前版本，且前端与 API 同域。
- “配对码已过期”：网页重新生成并在 5 分钟内确认。
- “等待已配对设备”：保持 iPhone App 在前台或 Mac App 运行，确认服务网址一致。
- 同一部署使用 `workers.dev` 和自定义域名时，App 按域名隔离身份；请选择一个网址长期使用。

更新代码后，在相同目录运行 `npm ci && npm run deploy`。iOS 与服务端协议保持兼容时，不需要重新安装 App。

## 从旧版升级到加密版本

先安装支持协议 v3 的 App，再更新同名 Worker 和网页，刷新网页重新配对。升级期间可能暂时无法同步，手机本机笔记保留。旧短码和旧网页授权不可继续使用；服务不允许回退到明文同步。


## 3.2 多设备同步升级

更新原生 App 与同名 Web / Worker 后，可以在新设备生成原生配对码，让已有设备授权并双向合并笔记。此升级保留 3.1 的加密网页授权和本机笔记，不需要重建 Durable Object 命名空间。新增数据库列使用兼容迁移；不要删除既有迁移历史。设备授权 365 天，网页授权 7 天。构建 [macOS 客户端](../macos/README.md) 后，可让 Mac 常驻接入各台 iPhone；具体在线边界见 [多设备同步](多设备同步.md)。

## 与官网分开发布

官网维护者使用 `npm run build:site` 和 `npm run deploy:site`；官网输出位于 `dist/site/`，配置为 `wrangler.site.jsonc`，本机部署目标放在 `.deploy.site.local.json`。它保留首页、下载、政策页面和 `/note`。自部署继续使用 `.deploy.local.json`，两者不共用本机部署目标。详见[官网发布说明](隐私政策与发布.md)。
